# Skia 3 (Graphite) — upgrade plan, 2026-10-17

Branch `mobile-skia-3`. Built and checked on the Android emulator; iOS not yet run.
Reference: islam.se did the same move today (`0ba963f`, `apps/mobile/docs/performance-expo58.md`).

## Why

- `@shopify/react-native-skia` 2.x is the old line; v3 is published as `react-native-skia`.
- Graphite/Dawn: the scene is recorded once per React commit, the UI thread only applies
  animated values, and a native thread pool replays the scene. Our Perfetto traces of a
  globe drag were Skia picture replay on the UI thread (`warp` over three `SkPicture`s).
- New primitives worth trying on the globe (ranked under "Opportunities").

Font, Paint, Picture, RSXform, Matrix4, `select`, `useTexture`, `useTypeface` and the

## Decision: devices without Vulkan 1.1

v3's library manifest declares `android.hardware.vulkan.version 0x401000 required="true"`.
Play stops serving the app to devices without Vulkan 1.1; on such a device every canvas,
the globe included, would be blank.

1. **Keep it required** (islam.se's choice). Check the excluded count first in Play Console
   → Device catalog, after uploading the build to internal testing.
2. Remove it (`tools:node="remove"` from a config plugin) and fall back when
   `Skia.gpu.isAvailable` is false. A globe-less app is not this app, so this means a
   second renderer; not worth it unless the excluded count is material.

No MapLibre here, so islam.se's `withSkiaVulkanAndroid` merge-conflict plugin is not needed.

## Device checks (when the emulator and a phone are free)

The emulator needs host Vulkan (islam.se had to restart it headless to get it); under
SwiftShader the numbers mean nothing.

- At rest renders zero frames: `dumpsys gfxinfo news.zuhd.app reset`, 5 s untouched.
  The native thread pool must not tick at rest.
- Globe drag, story swipe with a flight, landing fade (`fadeLayer` records a picture in a
  worklet on the UI thread every frame of `GROUND_FADE_MS`), pinch, tap pulse, found burst.
- `useTexture` sprites (glows, the famine/thermal sheet) and the tinted `drawAtlas` layers.
- Labels: `SubpixelAntiAlias` + no hinting under Graphite, no shimmer while turning.
- Colours: iOS now picks Display P3 on wide-gamut screens. Hold the `mark*` tokens to the
  web's in both themes (`feedback_globe_web_colours`); store screenshots will differ.
- Background → foreground, and many Metro reloads (the old "lost GL context" black screen).
- iOS on hardware: picture replay cost, the iOS-only per-frame native updates.
- Same flows on 2.14 and 3.x, counted in mounts and frames, not milliseconds. islam.se's
  emulator runs found no whole-app speedup; expect the gain, if any, on phones.

## First emulator A/B (2026-10-17)

`zuhd-qa` (API 35, x86_64, `-gpu host`; Skia 3 reports Vulkan on the host's Quadro M1200),
debug dev clients built from `master` (`08789f6a`, Skia 2.14) and this branch, the same
data. Flow `.argent/flows/globe-drag-perf-20261015.yaml` (four 600 ms drags), one warm-up,
then measured runs; frames from `dumpsys gfxinfo`, CPU from `/proc/<pid>/task/*/stat`.

| Four drags | Skia 2.14 (2 runs) | Skia 3.6.2 (2 runs, same load) |
|---|---|---|
| Frames drawn | 76, 70 | 128, 134 |
| Median frame | 97, 101 ms | 53, 48 ms |
| UI thread | 4.06, 4.13 s | 2.65, 2.80 s |
| JS thread | 0.60, 0.63 s | 1.97, 1.92 s |
| Android RenderThread | 0.64, 0.74 s | 2.39, 2.39 s |
| Skia render threads | — | 0.30–0.45 s |
| At rest, 5 s | 0 frames | 0 frames |

- The UI thread was saturated on 2.14: in a 9 s profile it was busy for 946 ms per second,
  25% of it in `librnskia` (picture replay) and most of the rest in the emulator's GL pipe.
  On 3.x it was busy for 409 ms per second, with Skia, Dawn and Vulkan at about 9% of that.
- The JS thread now does three times the work, because it is now what limits the frame
  rate: with the UI thread free, the reprojection reaction reaches `recordGlobeFrame` at
  its 32 ms throttle instead of whenever the UI thread let it. JS recording is the next
  bottleneck, which is what opportunity 4 addresses.
- RenderThread time is the emulator compositing the Skia surface each frame (GL pipe);
  it rises with the frame count and says little about a phone.
- Debug builds on an emulator. The direction is clear; the size on a phone is not.

## argent React profile, after the features (2026-10-17)

Four drags and four story swipes, dev build on `zuhd-qa`, session `20261017-203049`.

- Drags: zero React commits. The globe moves without React under Skia 3.
- `emitPrayerLines` was 102 ms of JS over the session (1,004 points a frame);
  `thin` cut the lines to 108 points within a pixel (`f72cce15`).
- A story landing commits 117–193 ms (dev), the same anatomy each time:
  `HomeScreen` re-renders on the new index (32 ms self, ~3 ms of it its own
  body in the CPU samples), `StoryDeck` and its three slots, the recycled slot
  rendering the next card (~68 ms subtree; its scroll handler closes over the
  slot's `position`), the card, the dock, eight labels that name the story's
  place. Much of the rest is dev-only: React 19's owner stacks
  (`errorStackGetter`, 67 ms over four landings) and the profiler's own diffing.
  No waste found that a small change removes; the globe's settled redraw runs
  beside the commit (its own `scheduleOnRN` task), not inside it.

## Opportunities, in order

1. **Free: replay off the UI thread.** No code. Measure UI-thread time in a drag on a
   phone, 2.14 against 3.x, before anything else.
2. **Mipmapped sprite textures** (`SkImage.makeTextureImage({ mipmapped: true })`) for the
   glow and hazard sprite sheets: cleaner small marks when zoomed out. Small change.
3. **10-bit Android surface** (`highBitDepth`): smoother ocean, rim and terminator
   gradients. Needs an opaque surface, so the canvas would paint its own background.
   Experiment.
4. **Record the globe off the JS thread.** `SkiaGraphiteView` + `SkGraphiteContext`
   (`beginRecording` → draw → `finishRecording` → `submit`) work from any runtime,
   including `createWorkletRuntime`. `recordGlobeFrame` (JS, behind the 32 ms throttle)
   could run on its own worklet runtime and hand frames to the view directly, freeing JS
   for the deck. Large: the geography, fonts and state would have to live in that runtime,
   and the inline-array-callback rule applies to every line of it. Only if (1) shows JS
   recording, not replay, is the bottleneck.
5. **A mesh globe** (`<Vertices>` / `Skia.MakeVertices` now take a `Float32Array`, copied in
   one go): a texture on a sphere mesh rebuilt as it turns, e.g. relief or a true day/night
   blend. The most visible change, and the one that most needs a decision against the
   foundation (images only when informational; the globe has no sky).
6. **Feedback surfaces** (`SkSurface.asImage()`, zero-copy): a flight's trail, a glow that
   builds over frames.
7. **WebGPU interop** (`MakeImageFromGPUTexture`, `getNativeDevice`): a WGSL globe under
   Skia's marks and labels. Needs `react-native-webgpu`; out of scope for now.

RuntimeEffect/SkSL, image filters, Paragraph and Atlas are unchanged in v3, so shader ideas
(atmosphere, terminator) were open on 2.14 already and do not argue for the upgrade.
